# Independent Friday/Saturday COT publication

The normal Morning analytics job refreshes CFTC only inside an accepted *new* SQL D1 generation. Its generation deduplication correctly skips already committed market receipts, but that also skipped independent weekly COT updates. A green queue run did not imply CFTC refresh or publication.

`Weekly COT refresh` is independent of D1/H4 collection. On Fridays it checks at 20:00, 21:00 and 22:00 UTC, covering the 15:30 New York release under either US DST offset. Saturday retries are 01:15 and 04:15 UTC (02:15/05:15 Prague winter, 03:15/06:15 summer). GitHub schedules can be delayed and CFTC holidays/outages can defer data; these are attempts, not a guaranteed publication SLA. The first scheduled check after a normal release is roughly 30 minutes later. Manual workflow dispatch also supports force refresh for same-date corrections.

Before touching SQL, one public aggregate CFTC query compares each contract's latest official position date with the committed manifest. No new date means no SQL wake-up, no recalculation and no hosting job. Retired/dropped contracts use their own real latest dates; they are not required to have this week's report. Network requests retry three times. No unrelated source is substituted.

On new data the existing CotService refreshes its correction window in the existing production SQL database. `--refresh-cot-export --output artifacts/cot-refresh` exports only COT using the same parser/BuildPoints and 26/52/156 windows as the normal exporter. It does not initialize a database/schema, import prices or advance market receipts. A partial upstream failure leaves the public snapshot untouched and the next run retries.

Staging validates all contract identities, expected latest official dates, historical count, content hashes, ordered report dates, nonnegative long/short/spread, net arithmetic and index bounds. It merges the COT files into a private copy of the committed site, preserves all price paths/identities, SQL generation and H4/backtest metadata. `sourceSnapshotAt` and `stockSnapshotAt` retain their original values; `exportedAt` is the assembled snapshot time and `cotSnapshotAt` identifies this independent observation. Screener and opportunity COT context are recalculated against unchanged prices. No synthetic recent candles or papertrade records are created.

Publication checks the original manifest hash (CAS), protected metadata and an explicit file allowlist before committing only generated COT/context files. Shared `seasonality-data-update` concurrency serializes repository data writers; a conflicting Git push is rejected, never force pushed or rebased. A successful `cot-publication` artifact triggers the existing static-hosting pipeline via workflow_run, because bot commits do not trigger push workflows. It does not overwrite daily collection health reports. A failure/no-op has no publication artifact and cannot deploy a candidate. Existing SQL/server-side COT becomes current when refreshed; public static graphs are verified separately after hosting.

Checks: `node Tools/cot-refresh-checks.cjs`, `dotnet run --project Tools/CotChecks/CotChecks.csproj -c Release`, solution build, offline full-site staging + both analytics builders + render-static-shell + static-site-checks, and public browser checks after the first real run. Original COT definitions, FX USD neutral-reference rule and running trading models are unchanged.
