# Historical H4 replay

`/backtesting/` runs automatically for EURUSD on opening; select another OANDA H4 instrument, all available instruments, and optional UTC date bounds to rerun. Runs in a dedicated Web Worker; cancellation terminates it without publishing a partial result. No SQL writes, trading orders, schedule changes, or imports into the prospective baseline/research. The page must remain open during calculation. No scheduled server-side backtest is implied.

The adapter `h4-backtest.js` invokes the **unchanged** `h4-paper.js` `update` at every historical close, with prefixes only. All trade geometry, costs, OCO, frozen zone identities, ambiguity and gap execution rules come from that engine, including the same FM detector. Admission happens at historical close; a fill requires a later candle. No reconstructed Work latency. Results differ from real historical publication/registration times and cannot be presented as a replay of actual live decisions.

Use only the current content-addressed published zone-price SQL sidecar; verify SHA-256 with native Web Crypto before running. The synchronous worker hash matches native SHA-256 in tests. The prefix passed to the engine strips unrelated full-snapshot metadata. Bars must pass the existing H4 validation without silent rejection. This is a replay of currently available possibly revised prices, not a historical vintage archive or all SQL data ever stored. The UI lists exact coverage per symbol.

Partition at non-adjacent H4 timestamps using the original engine's ordinary-weekend exception. No exchange-holiday calendar is invented: Christmas/New Year gaps are visible and split the sample. Each segment seeds 200 bars before first admission, a fixed warmup assumption for ATR(96)/structure. It does not prove convergence to an infinitely long Pine history. Date `from` restricts registrations, retaining earlier segment bars for indicator history. UTC `to` includes candle closes through that day. No positions imported from before the chosen registration start. Active positions/pending setups before a missing segment remain `needs_data` with `HISTORY_GAP`; end-of-test scenarios remain unresolved, never forcibly marked flat or assigned zero-return trades. Subsequent segments start independently after warmup.

Statistics: same closed TP/SL summary, plus PF and double-cost stress. Only unambiguous completed trades enter R, mean, win rate and closed-equity drawdown. No account-level portfolio, sizing or correlation adjustment. No winner selection, optimizer or claimed untouched holdout. Financing remains unmodeled. The retrospective sample does not count toward the prospective 100-trade checkpoint.

Table sorts the complete result before pagination. Modal includes frozen zone bounds, confirmation/origin, BOS/volume evidence, entry/SL/TP, entry/exit proof-candle markers, original risk/reward rectangles, drawing toolbar and Prague/DST times. JSON download bundles report/events and original selected candle inputs; source path/hash/model/config/version allow audit/replay while old public snapshots may later be retired.

Checks: `node Tools/h4-backtest-checks.cjs`, `node Tools/h4-backtest-browser-checks.cjs <rendered-site>`, original paper/research checks, solution build and actual ASP.NET startup. Fixtures stay local and never enter SQL.
