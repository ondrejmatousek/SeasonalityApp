# Work -> Azure HTTP transport probe (NOT ingestion)

`POST /api/market-daily/probe` is a validation-only experiment. It never writes SQL, files, market overlays or background jobs and does not alter the GitHub data flow. It returns a deterministic payload checksum/receipt, bar count, `persisted:false`, `analyticsTriggered:false`, `completionValidated:false`. A 200 proves authenticated HTTP transport and structural/source/OHLC checks, NOT independently verified candle completion or ingestion.

Default: disabled, with explicit `MARKET_DAILY_PROBE_DISABLED` JSON and HTTP 404. Enable ONLY with Azure application setting `MarketDailyProbe__Enabled=true` and a dedicated high-entropy `MARKET_DAILY_PROBE_TOKEN` (32+ characters), stored securely on both the server and the authorized caller. Bearer token stays out of source, reports, URLs, request bodies and client JavaScript. No credential is created/exported by deployment. Missing/weak server key fails closed with 503; absent/wrong request key returns 401. HTTPS is required for remote callers.

Limits: 256 KiB, 1-39 distinct registered sources, 30 requests/IP/minute, body-read timeout 10 seconds. It reads the same deployed price-source bundle, with the existing cash-index symbol aliases; no new provider mapping or fallback is introduced. Supports only the current schemaVersion 1 / timeframe 1D envelope. No payload or Authorization header is logged by this code.

Local runtime verification: prepare the current read-only price-source bundle first (existing seed restore/prepare commands), `dotnet build SeasonalityApp.slnx -c Release`, then `node Tools/market-daily-probe-checks.cjs`. An already prepared isolated real bundle can be selected with `MARKET_DAILY_PROBE_TEST_BUNDLE`. The backend deployment workflow performs preparation and this HTTP regression before publishing. The test launches the actual DLL using explicit `--market-daily-probe-only`, with no SQL registration/schema initialization, a random in-memory test token and only localhost HTTP. Normal application startup/SQL behavior is unchanged. Probe-only mode exposes only this experimental route and permits HTTP only on loopback for this isolated test. Enabled remote requests must be HTTPS; do not enable AllowLocalHttp in Azure.

Azure backend: `https://seasonality-gbfhasdjamcnf6dm.westeurope-01.azurewebsites.net`. First check Work's actual POST tool/network permissions against the disabled endpoint, expecting 404 with the specific disabled JSON. This is a transport-only check, not an authenticated success. Then configure the dedicated secret safely and test authenticated 200 before considering any production ingestion. A GitHub write tool or a web GET tool alone does not establish POST capability. If necessary, a separately approved narrow MCP tool could expose the operation, but no plugin/credential integration is implemented here.
